Approuver un paiement
avant que l'utilisateur paie.

Le handler d'origine renvoie { approved: true } sans jamais contacter Pi. Le client croit que tout va bien, puis Pi rejette le /complete — et n'importe qui peut spammer l'endpoint.

Le code d'origine

// Approuve côté serveur avant que l'user paie
export async function POST(req) {
  const { paymentId } = await req.json()
  // Vérif serveur : fetch(...) — jamais exécutée
  return Response.json({ approved: true })
}
  • Aucun appel à /v2/payments/{id}/approve
  • Aucune validation du paymentId
  • Montant et orderId contrôlés par le client
  • Endpoint ouvert au spam
Corrigé

Les 5 garde-fous

  1. 1
    Refuser si la config manque. Sans PI_API_KEY, on renvoie une 500 explicite.
  2. 2
    Valider l'entrée. JSON invalide ou paymentId non-string → 400.
  3. 3
    Appeler Pi en POST avec Authorization: Key …, sans body.
  4. 4
    Comparer en base : montant, orderId et uid attendus, jamais ceux du client.
  5. 5
    Rendre l'approve idempotent. « already approved » = succès.

Le handler vérifié

app/api/pi/approve/route.js 
export async function POST(req) {
  if (!process.env.PI_API_KEY) {
    return Response.json({ error: "server misconfigured" }, { status: 500 })
  }

  let body
  try { body = await req.json() }
  catch { return Response.json({ error: "invalid json" }, { status: 400 }) }

  const { paymentId } = body ?? {}
  if (typeof paymentId !== "string" || !paymentId) {
    return Response.json({ error: "paymentId required" }, { status: 400 })
  }

  const res = await fetch(
    `https://api.minepi.com/v2/payments/${encodeURIComponent(paymentId)}/approve`,
    {
      method: "POST", // pas de body
      headers: { Authorization: `Key ${process.env.PI_API_KEY}` },
      cache: "no-store",
    }
  )

  if (!res.ok) {
    const already = res.status === 400 &&
      (await res.clone().text()).includes("already")
    if (!already) {
      const detail = await res.text()
      return Response.json({ error: "pi approve failed", detail }, { status: 502 })
    }
  }

  const payment = await res.json()

  // Ne fais jamais confiance au montant ou à l'orderId du client.
  const expected = await db.orders.get(payment.metadata?.orderId)
  if (!expected ||
      payment.amount !== expected.amount ||
      payment.metadata?.uid !== session.user.id) {
    return Response.json({ error: "payment mismatch" }, { status: 400 })
  }

  await db.orders.markApproved(expected.id, payment.identifier)
  return Response.json({ approved: true })
}
Après le paiement : sur /complete, refais un GET /v2/payments/{id} et vérifie status === "approved" avant de livrer quoi que ce soit.
